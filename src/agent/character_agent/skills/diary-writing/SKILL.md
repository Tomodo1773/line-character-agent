# 日記登録スキル

## スキルの役割

**あなたは日記を「書く」「まとめる」役ではない**。ユーザが送ってきた文章を、ほぼそのまま日記として Cosmos DB に登録することだけがこのスキルの仕事。内容の生成・要約・再構成はしない。ユーザの文章こそが日記本文である。

## いつ使うか

- ユーザが「日記を書きたい」「今日のことを記録して」「昨日の日記に追記して」などと言ったとき
- ユーザが日付に言及しつつ、日記として残したい本文を渡してきたとき（「昨日の日記。〜」など）

## 対話の進め方

ユーザは「今から昨日の日記を書く」のように**宣言してから本文を送ってくる**ことが多い。

- 宣言だけで本文が無いときは、日付だけ確定して「どうぞ」と促し、**次のメッセージを待つ**。深掘りや追加質問はしない。
- 宣言と本文が同じメッセージに入っているときは、そのまま登録まで進める。

## ワークフロー

### 1. 日付の確定

- `get_current_datetime` で今日の日付を確認する。「昨日」「一昨日」はここから計算する
- ユーザが日付を指定していればその日付を使う
- 指定がないときは**前日**を使う。ユーザは翌日に日記を書くのが通常のため
- ツールに渡す日付は必ず YYYY-MM-DD 形式

### 2. モードの決定

- `diary_search` に `start_date` と `end_date` の両方へ対象日を指定して、その日の日記が既にあるか確認する（`query_text` は指定しない）
- 見つからない → **新規作成モード**（4-A へ）
- 見つかった → **追記モード**（4-B へ）

### 3. 日記本文の取り出し

ユーザのメッセージから、ツールに渡す本文を取り出す。**内容の生成・加筆・要約・再構成は一切しない**。

取り出す際に行ってよい処理は以下の3つのみ。**これ以外の変更はしない**。

- **メタ発話の除去**: 日記本文ではない前置きや依頼文を取り除く
  - 例: 「昨日の日記を書きます」「以下の内容で日記作って」「お願いします」
- **不要な句読点の削除**: 連続した句読点や文中で浮いている句読点など、明らかに不要なものだけ取り除く
- **改行の追加**: 話題が変わるところに改行を入れる

**やってはいけないこと**（ユーザが自分でそう書いて送ってきた場合を除く）:

- 見出し（`#` `##` 等）を付けない。日付は日記のフィールドとして持つので本文には不要
- 箇条書き（`-` `*` `1.` 等）にしない
- 内容を要約・言い換え・体裁よく書き直さない
- 「ひとこと」「感想」「まとめ」など、ユーザが書いていないセクションを追加しない
- ユーザの口調やスタイルを変えない（です/ます、だ/である等はそのまま）

### 4. 登録

いずれのモードでも `summary` にはその日を表す**2-5語の短いフレーズ**を渡す。感情は入れず、体言止めまたは短い文で、何をしたか・誰とだったか・どこでだったかが分かるように書く（例: 「家族とディズニーランド」「会社で健康診断」）。これは検索用ではなく、直近の出来事を思い出すためのダイジェストに記録される。

#### 4-A. 新規作成モード

- セクション3で取り出した本文を `diary_create` に渡す

#### 4-B. 追記モード

- `diary_search` で取得した既存本文の**末尾に**、セクション3で取り出した本文を連結する
  - 既存本文と新規分の間には空行を1つ挟む
  - 既存本文そのものは編集しない。末尾への追加のみで、統合・並べ替え・再構成はしない
- 結合した全文を `diary_update` に渡す

### 5. 完了報告

- 登録できたことをユーザに伝える
- ユーザの日記に対して、キャラクターとして一言コメントを添える

## 修正・削除の依頼

日記を書く依頼ではなく、既存の日記への操作を頼まれたときは、このスキルの手順ではなく該当するツールを直接使う。

- 本文の修正 → `diary_search` で全文を取得し、直した全文を `diary_update` に渡す
- 削除・日付の間違い → `diary-maintenance` スキルを読み、その手順に従う。対象の確認と削除前の同意が必須なので、`diary_delete` や `diary_rename` をここから直接呼ばない
