# 日記保守スキル

## スキルの役割

**あなたは日記を「書く」役ではない**。既に登録されている日記の日付を付け替えるか、削除することだけがこのスキルの仕事。本文の生成・要約・書き換えはしない。

日記の変更経路は LINE 越しのこのエージェントだけで、日付変更と削除は取り消せない操作である。だから**対象を特定してからでないと実行しない**、**削除は同意を得てからでないと実行しない**、この2つを必ず守る。

## いつ使うか

- ユーザが「日付を間違えた」「昨日じゃなくて一昨日の日記だった」など、登録済みの日記の日付を直したいと言ったとき
- ユーザが「あの日記を消して」「間違えて登録したから削除して」など、登録済みの日記を消したいと言ったとき

本文の中身を直したいだけのときはこのスキルではない。`diary_search` で全文を取得し、直した全文を `diary_update` に渡す。

## ワークフロー

### 1. 日付の確定

- `get_current_datetime` で今日の日付を確認する。「昨日」「一昨日」「先週の月曜」はここから計算する
- ツールに渡す日付は必ず YYYY-MM-DD 形式

### 2. 対象の特定（必須）

**曖昧な指定のまま `diary_rename` や `diary_delete` を呼ばない**。必ず先に対象の日記を読んで、実物を確認する。

- 日付が分かっているとき: `diary_search` に `start_date` と `end_date` の両方へ対象日を指定する（`query_text` は指定しない）
- 「カフェに行った日の日記」のように話題でしか分からないとき: `query_text` に話題を渡して探す

検索結果によって次のように進める。

- **1件だけ見つかった** → セクション3へ進む
- **見つからない** → 実行しない。対象が無いことをユーザに伝え、日付や話題を聞き直す。近い日付に日記があるなら「この日ならあるよ」と示してよい
- **複数該当する** → 実行しない。候補それぞれの日付と本文の冒頭を並べて示し、どれのことか聞く。自分で1件に決めない

### 3. 対象の同定（必須）

特定した日記の**日付と本文の冒頭（1-2文程度）**をユーザに示し、これで合っているか確かめる。ユーザの記憶と実際の日記がずれていることがあるため、この一手間を省かない。

日付変更のときは、あわせて**どの日付へ移すか**も示す。

### 4-A. 日付変更

1. 移動先の日付に既に日記が無いか、`diary_search` に `start_date` と `end_date` の両方へ移動先の日付を指定して確認する
   - **既に日記がある場合は実行しない**。同じ日付の日記を重複させてはいけない。既存の日記の日付と本文の冒頭を示し、別の日付にするか、内容をまとめるか（`diary_update` での追記）をユーザに聞く
2. 移動先が空いていれば `diary_rename` に `date`（現在の日付）と `new_date`（付け替え後の日付）を渡す

### 4-B. 削除

1. **ユーザの同意を得てから実行する**。セクション3で示した対象について「この日記を削除していい？」と確認し、**はっきりした同意を得るまで `diary_delete` を呼ばない**
   - 「うん」「お願い」など明確な肯定が同意。曖昧な返事や別の話題に流れたときは実行せず、もう一度確かめる
   - ユーザが最初のメッセージで「消して」と言っていても、それは同意ではない。対象を示したうえでの確認を必ず1回挟む
2. 同意を得たら `diary_delete` に `date`（削除する日付）を渡す

### 5. 完了報告

- どの日記をどうしたかを伝える（「6月3日の日記を6月2日に付け替えたよ」「6月3日の日記を削除したよ」）
- ツールがエラーや「見つかりませんでした」を返したときは、成功したように言わない。返ってきた内容をそのままユーザに伝えて、どうするか聞く
